# Gameplay experience redesign

PR43 is deliberately a presentation-only foundation. The top HUD separates back navigation, prominent chapter and level identity, the move counter, help, Undo, Return to safety and Settings. Icon artwork is inline original SVG, accompanied by visible labels on spacious layouts and accessible names/tooltips at smaller sizes. Grid and close-up belong to a slim in-stage view rail; Objects is the single gold action until PR44. Camera, axes, coordinate picker, guidance, audio, motion, focus view and Reset are grouped inside Settings. Reset asks for confirmation, pauses simulation while open, and preserves past best scores. Undo and Return keep their original semantics.

The stage has three tracks: quick tools, a measured canvas-only playfield, and a dock containing circular movement/climb buttons on the left and a larger jump button on the right. The dock is in the stage, not over geometry. This deliberate choice prevents controls obscuring a vertex, axis, player or exit on cramped screens; the actual canvas is measured with ResizeObserver and retains a minimum height of 138 CSS pixels. The page reflows/scrolls when necessary rather than clipping a mathematical panel. Keyboard and touch still use the existing independent held-input controller. Climb buttons follow actual ladder availability; controls remain hidden while picking, inspecting or casting as before. The footer presents compact status and tutorial guidance. Touch targets are at least 44 CSS pixels, keyboard focus is visible, and the existing inspector remains accessible. No geometry, physics, scoring, storage, permissions or cast behavior changes.

PR44 replaces the Objects mode with direct selection and persistent magical outlines, four spell icons using the existing identity assets, and non-modal spell editing while movement remains independent. PR45/46 add graphical parameter picking through the exact shared camera/math pipeline; typed inputs remain. PR47 updates tutorials and reviews all sizes, safe casting, preview validity, placement, progress and final real-device visual acceptance. Existing full campaign, production smoke, menu and workshop QA stay mandatory. Focused gameplay HUD browser tests additionally cover the actual controls, settings and reset across layouts. Rendered screenshots and classroom device visual approval remain separate from automated geometry checks.
